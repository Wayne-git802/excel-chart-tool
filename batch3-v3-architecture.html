🔍 Batch 3 v3 — InsightEngine 终版架构

Dedup→Cluster(共识放大) · HypothesisPruner · ExecutionSemantics · source_count 加权

🔵 InsightCluster (v3 核心改动)

  • ❌ 旧: Dedup → 丢弃重复 → signal 变弱
  • ✅ 新: Cluster → 合并 + source_count 加权
  • • conf_agg = max(conf) × (1 + 0.15 × n_sources)
  • • 3 检测器共识 → 置信度 × 1.3
  • • 输出 ClusteredInsight(rep, sources, conf_agg)
  • • source_count 直接进入 ranking 公式

✂️ HypothesisPruner (防爆炸)

  • • 规则①: 每个 insight 最多 3 条假设
  • • 规则②: score < 0.4 的假设不进 graph
  • • 规则③: 用户未点击的分支不展开
  • • 预期: 初始 graph 5-8 个节点 (可控)
  • • 点击 [展开] → 懒加载子节点

⚡ Hypothesis Execution

  • • 优先级: 比 Batch 4 UI 更高
  • • LLM + 数据查询 → 验证假设
  • • 结果: confirmed / rejected / uncertain
  • • confirmed → 生成深度图表
  • • rejected → 记录原因隐藏
  • • uncertain → 标记并提示用户

最终评分公式

  • effect_size × 0.35
  • surprise × 0.10 (须过 SigGate)
  • actionable × 0.30
  • confidence × 0.25 (含 source_count 加权)
  • source_count ≥ 2 → confidence 额外加成
  • 阈值: ≥ 0.3 → 推送 (共识信号优先)

核心设计原则

  • 共识即信号: 3 个检测器比 1 个更可信
  • 懒惰展开: graph 不爆炸，用户点才展开
  • 执行优先于展示: 先验证假设，再画 UI
  • 不打扰优先: 默认 analyze，需授权才推
  • 噪音过滤链: Cluster → SigGate → Pruner
